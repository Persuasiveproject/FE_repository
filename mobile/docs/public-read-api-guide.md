# 홈·토론·의견 API 조회 안내

확인일: 2026-11-09. 작업 브랜치: `feat/public-api-integration`.
서버: <https://dev-api.yeongup.shop>.
BE 확인 기준: `develop`의 `66685e5454dd198f112a6e150ee31163574934c9`.

## 1. 이번에 사용할 수 있는 범위

현재 `api` 모드는 비로그인 **읽기 기능**을 지원합니다.

| 화면 | 실제 요청과 동작 |
| --- | --- |
| 홈 | GET `/v1/home`의 인기·추천 배열을 표시. 카테고리 이름은 `/v1/categories`와 연결 |
| 목록 | GET `/v1/debates`에서 제목 검색·카테고리·진행/종료 필터·다음 페이지 조회 |
| 토론 상세 | GET `/v1/debates/{id}`의 제목·본문·카테고리·참여자·마감 시각 표시 |
| 의견 | GET `/v1/debates/{id}/posts`의 입장별 필터·최신/추천순·다음 페이지 조회 |
| 답글 펼치기·전체 화면 | GET `/v1/posts/{postId}/thread`로 해당 의견의 직계 답글 조회·다음 페이지 이동 |

로고·글꼴·툴바·카드·토론 주제 카드·가로 입장 필터·업보트/다운보트 배치는 기존 공통 부품을 사용합니다.
`mock` 모드는 기존 생성·참여·의견 등록·입장 변경 등의 전체 데모 동작을 유지합니다.

## 2. 아직 지원하지 않는 범위

로그인·회원가입·본인확인·글쓰기·참여·업보트·다운보트·영업·코인 처리는 실제 서버에 연결하지 않았습니다.
API 모드의 의견 카드에서 투표·영업 버튼은 모양을 유지하고 비활성화합니다. 신고 버튼은 기존처럼 안내만 표시합니다.
결과 화면·AI 요약 연결도 이번 범위 밖입니다. API 모드의 진입 버튼은 준비 상태로 표시합니다.
인증이 필요한 경로는 기존 `api-client.ts`의 가드를 유지하고, 토큰을 임의로 넣거나 인증을 우회하지 않습니다.

BE PR #37에서 **GET 내 입장**이 제거됐습니다. 이번 코드는 해당 GET을 호출하지 않습니다.
로그인 연동 후 입장 정보는 상세 응답의 `myParticipation`을 기준으로 연결해야 합니다.

## 3. 서버 데이터의 의미를 유지한 부분

- 큰 ID는 모두 문자열입니다. `Number(id)`로 바꾸지 않습니다. `ai-class` 같은 데모 ID를 서버로 보내지 않습니다.
- 목록·홈에는 본문 설명이 없습니다. 가짜 요약을 채우거나 토론마다 상세 요청을 추가하지 않습니다.
- 상세의 `endsAt=null`은 “마감 시간 미정”으로 표시합니다. 임의의 마감 시각을 만들지 않습니다.
- 의견 카드의 작성자는 `anonymousNo`를 이용한 “익명 N”입니다. 실제 계정 ID는 만들거나 노출하지 않습니다.
- 서버에 없는 `myVote`는 추가하지 않습니다. 인증 후 선택 상태를 연결하려면 BE와 응답 계약을 확정해야 합니다.
- 루트 의견의 입장/정렬 필터는 서버에 전달합니다. 정렬 이름은 UI의 “추천순”을 BE의 `upvotes`로 변환합니다.
- 답글 API는 입장 필터를 지원하지 않습니다. 답글 전체 화면의 입장 필터는 **현재 불러온 답글**에 적용하며 화면에도 표시합니다.
- 필터·정렬·대상 ID 변경 시 목록과 cursor를 초기화합니다. 다음 페이지 실패는 기존 글을 남기고 재시도할 수 있습니다.
- 페이지 사이 중복 글은 합치고 cursor가 반복되면 오류를 표시합니다. 토론/부모가 다른 글이 응답에 섞이면 거부합니다.
- 실제 서버 오류를 예시 데이터로 대체하지 않습니다.

### 답글 원문에 관한 제약

현재 #31 응답에는 `replies`와 `meta.nextCursor`만 있고 원문 의견은 없습니다.
목록에서 봤던 공개 의견을 최대 200개까지 메모리에 보관하여 답글 전체 화면의 원문으로 표시합니다.
앱/웹을 재시작하거나 주소를 직접 열면 원문이 없을 수 있으며, 이 경우 토론으로 돌아가는 안내를 표시합니다.
저장된 원문은 마지막 목록 조회 시점의 내용입니다. 전체 의견 페이지를 훑어서 찾거나 원문을 임의로 만들지 않습니다.
직접 주소 진입 시에도 원문을 항상 제공하려면 BE에서 단일 의견 조회 또는 thread에 원문을 포함하는 계약이 필요합니다.

## 4. 실행과 확인

`mobile/.env.local`은 다음 설정이며 Git에 포함되지 않습니다.

```dotenv
EXPO_PUBLIC_API_BASE_URL=https://dev-api.yeongup.shop
EXPO_PUBLIC_DATA_SOURCE=api
```

```powershell
cd C:\dev\FE_repository\mobile
npm.cmd start
```

실행 중이던 Expo를 종료한 뒤 다시 시작하고 앱을 완전히 새로고침합니다.
홈 → 검색/더보기 → 토론 카드 → 답글 펼치기/전체 화면 순서로 확인합니다.
현재 서버에 공개 카테고리·토론이 없어 홈과 목록은 빈 상태가 정상입니다.
실제 내용이 있는 화면 검증에는 BE의 테스트 데이터가 필요합니다. 이번 작업에서는 서버 데이터를 생성하지 않았습니다.
전체 데모를 확인하려면 모드를 `mock`으로 바꾸고 다시 실행합니다.

### 웹 연결의 남은 조건

개발 서버는 확인 당시 `Origin: http://localhost:8082`에 대한 `Access-Control-Allow-Origin`을 반환하지 않았습니다.
PowerShell/Node의 HTTP 성공과 브라우저 연결 성공은 다릅니다. BE에 실제 개발 웹 origin을 허용하도록 요청해야 합니다.
FE의 `no-cors` 설정으로 JSON 응답을 읽을 수는 없습니다. 모바일 실기기 동작은 별도로 확인해야 합니다.

## 5. 파일별 역할과 수정 방법

| 파일 | 간단한 역할 |
| --- | --- |
| `src/services/api-values.ts` | 실제 JSON의 문자열·ID·숫자·UTC 시각·cursor 검사 |
| `src/services/public-api.ts` | 기존 카테고리·목록 요청과 카드 변환. 공통 목록 DTO 검사 재사용 |
| `src/services/public-debate-api.ts` | 홈·상세·의견·답글 요청, 응답 검사, 익명 카드 변환, 최근 원문 보관 |
| `src/services/discussions.ts` | 홈에서 모드에 따라 실제 피드 또는 기존 데모 사용 |
| `src/types/api.ts` | 이번 조회에서 사용하는 서버 데이터 필드 정의 |
| `src/types/core.ts` | 실제 작성자 ID 없이도 쓸 수 있는 `OpinionCardData` 추가 |
| `src/features/debates/api-detail-screen.tsx` | 서버 상세 표시. 주제 카드는 기존 `topic-summary-card.tsx` 재사용 |
| `src/features/opinions/public-opinion-feed.tsx` | 의견·답글 필터, 펼치기, 페이지 조회·재시도 |
| `src/features/opinions/api-thread-screen.tsx` | 실제 답글 전체 화면과 원문이 없는 경우의 안내 |
| `src/features/debates/detail-screen.tsx`, `src/features/opinions/thread-screen.tsx` | 모드별 화면 선택. 기존 데모 로직은 유지 |
| `src/features/opinions/opinion-card.tsx` | 표시용 데이터 타입을 받도록 변경. 기존 카드 스타일 유지 |
| `src/components/page.tsx` | API 모드의 조회 가능 범위 안내 |
| `tests/public-debate-api.test.ts` | 홈·상세·익명 의견·관계 검증·페이지·오류 계약 테스트 |
| `scripts/check-public-api.ts` | 실제 홈·목록을 조회하고 서버 데이터가 있으면 상세·의견·답글까지 확인 |

`types/api.ts`의 상세·의견 타입과 검증기는 **이번 화면에서 사용하는 공개 필드**를 다룹니다.
이미지·출처 링크·배지·인증/참여 정보 전체를 구현·검증한 것은 아닙니다. 후속 화면에 추가할 때 필드 검증도 함께 확장하세요.

## 6. 다음 작업

1. BE에 카테고리·공개 토론·서로 다른 입장의 의견·답글 테스트 데이터와 웹 CORS 설정을 요청합니다.
2. 실제 데이터로 홈/목록 → 상세 → 필터·정렬 → 답글 → 다음 페이지를 기기와 웹에서 확인합니다.
3. 로그인 계약을 확정하고 내 정보·`myParticipation`·내 투표 상태를 연결합니다.
4. 인증·멱등성 키를 적용한 참여/게시/의견/입장 변경과 결과·AI 요약을 순차 연결합니다.

초기 목록 연결 작업의 이력과 설정 설명은 [1단계 기록](public-api-integration.md)을 참고하세요.

## 7. 이번 검증 결과

- `npm.cmd run typecheck`, `npm.cmd run lint`, `git diff --check`: 통과.
- `npm.cmd test`: 기존/공개 목록/홈·상세·의견 계약 테스트 총 **38개 통과**.
- `npm.cmd run test:api`: 실제 서버의 홈·카테고리·진행/종료 목록 응답 형식 확인. 모두 빈 목록.
- 실제 상세·의견·답글의 내용 있는 응답 검사는 서버 토론이 없어 보류. 성공·오류·페이지 처리는 고정 응답 단위 테스트로 검사.
- API 모드 웹 실행 후 23개 경로 HTTP 200·제목·SSR 구조 검사 통과. 클릭·화면 배치 검사는 아님.
- Android/iOS/Web 전체 번들 생성 통과: `.expo/public-read-api-export`.
- 웹 CORS 미설정과 모바일 실기기·실데이터 통합 검증은 남아 있음.

검사용 웹 서버는 종료했습니다. BE 파일·서버 데이터는 수정하지 않았습니다.
이 변경은 `feat/public-api-integration`에서 검토하며, main 병합은 별도로 진행합니다.
