# 토론 화면 부분 디자인 수정

작업일: 2026-11-08. 브랜치: `feat/core-screens`. 이전 핵심 화면 작업 위에서 수정했습니다.

## 바뀐 부분

- **상단 주제 카드**: Figma DB-200의 토론 주제 영역(105:725)을 기준으로 수정했습니다. 배경 #EAF7FD, 안쪽 여백 16, 항목 간격 8입니다.
  마감 시간은 12px/19px·#0EA5E9, 제목은 18px/27px·굵기 700·#172B3A, 설명은 12px/19px·#637381입니다.
  글꼴은 시스템 기본을 유지하며, 카드 바깥의 참여 정보·입장 표시·행동 버튼은 유지했습니다.
- **의견 필터**: 전체·찬성·반대·유보가 1×4 한 줄로 나옵니다. 버튼의 색·글꼴·선택 상태·기능은 유지하고 가로 배치와 간격만 조정했습니다.
  가입·생성·참여 목록 등 다른 곳의 선택 버튼은 기존 배치입니다.
- **의견 카드**: 테두리 색·배경·본문·시간 표시는 유지했습니다. 아래쪽 왼편은 `↑ 현재 표수 ↓`, 오른편은 `영업 | 답글 펼치기`입니다.
  표수는 업보트 수에서 다운보트 수를 뺀 값입니다. 기존 투표 선택·전환·취소·자기 글 투표 차단은 유지됩니다.
- **영업**: 기존 '이 의견에 설득됐어요' 동작으로 연결합니다. 선택한 의견 또는 답글을 근거로 입장 변경 화면을 엽니다.
- **답글 펼치기**: 카드 아래에 답글을 조회하고 다시 접을 수 있습니다. 펼친 영역에서 답글 작성과 기존 전체 답글 화면으로 이동할 수 있습니다.
- **신고**: 카드 오른쪽 위 작은 버튼입니다. 누르면 연결 준비 중 안내가 뜹니다. 실제 신고 전송·접수 기록을 만들지는 않습니다.
  서버 신고 계약이 나오면 안내를 실제 신고 폼/요청으로 교체합니다.

## 수정 파일의 역할

모든 경로는 `mobile/` 기준입니다.

| 파일 | 역할 |
| --- | --- |
| `src/features/debates/topic-summary-card.tsx` (추가) | 상단 카드만 독립적으로 관리. 이 카드의 색·글자 크기·간격을 수정할 곳 |
| `src/features/debates/detail-screen.tsx` | 새 카드 연결, 필터 가로 배치, 펼친 의견 ID 목록 관리 |
| `src/features/core/choice-group.tsx` | 선택적인 `layout="row"` 옵션 추가. 기본 grid 모양은 유지 |
| `src/features/opinions/opinion-card.tsx` | 표수·업/다운 버튼·영업·펼치기·신고 안내 표시 |
| `src/features/opinions/opinion-replies.tsx` (추가) | 펼쳤을 때만 답글 조회, 로딩·재시도·투표·작성/전체 화면 이동 |
| `src/features/opinions/thread-screen.tsx` | 같은 의견 카드 UI와 가로 필터를 전체 답글 화면에서도 사용 |
| `src/features/debates/stance-screen.tsx` | 답글의 영업 버튼으로 진입할 때 선택 근거 답글도 조회해 표시 |

홈·툴바·공통 색상/글꼴 토큰·기존 토론 목록 카드·서버/Mock 데이터 모델은 이번 수정에서 변경하지 않았습니다.
새 패키지나 화면 경로를 추가하지 않았습니다.

## 확인 방법과 범위

1. 홈의 인기 토론을 열어 상단 카드의 크기·색·순서를 확인합니다.
2. 전체·찬성·반대·유보가 가로로 나오고 기존처럼 필터링되는지 확인합니다.
3. 데모 로그인 후 토론에 참여합니다. 업보트를 선택·취소하거나 다운보트로 바꿔 가운데 표수가 갱신되는지 확인합니다.
4. 답글 펼치기·접기, 펼친 답글의 투표, 답글 작성과 전체 답글 화면 이동을 확인합니다.
5. 영업 버튼에서 선택한 글을 근거로 입장을 바꿀 수 있는지 확인합니다.
6. 오른쪽 위 신고 버튼을 눌러 안내를 열고 닫습니다. 현재 실제 신고는 접수되지 않습니다.

자동 검사에서 TypeScript·ESLint, 기존 데이터 동작 테스트 19개, 웹 경로 검사 23개가 통과했습니다.
Android/iOS/Web export도 통과했으며 산출물은 Git에서 제외되는 `.expo/discussion-ui-export`에 생성했습니다.
실제 컴포넌트를 React Native Web으로 정적 렌더링해 상단 카드 색상, 필터 버튼 4개, 업보트→표수→다운보트→영업 순서와 신고/답글 버튼도 검사해 통과했습니다.
정적 렌더링은 클릭·실제 픽셀 배치 검사가 아닙니다. 브라우저 도구의 연결 호스트가 없어 직접 클릭/스크린샷 검사는 진행하지 못했습니다.
Figma는 코드의 수치와 배치 기준으로 확인했으며, 실제 기기에서 작은 화면·큰 글자·긴 표수의 표시를 추가 확인해야 합니다.
