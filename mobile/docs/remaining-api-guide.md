## 사용 위치

| 기능 | 앱에서 여는 방법 | API |
| --- | --- | --- |
| AI 요약 | 토론 상세 → AI 요약 | GET `/v1/debates/{id}/summary` |
| 서버 기준 남은 시간 | 토론 상세에서 자동 표시 | GET `/v1/debates/{id}/timing` |
| 내 입장 변경 이력 | 참여한 토론 상세 → 내 입장 변경 이력 | GET `/v1/debates/{id}/me/events` |
| 알림 | 마이 → 알림 → 전체/안 읽은 알림 | GET `/v1/me/notifications` |
| 초안 저장·수정 | 만들기 → 내용 입력 → 게시 전 초안 저장/초안 변경 저장 | POST `/v1/debates`, PATCH `/v1/debates/{id}` |
| 이어 쓰기 | 마이 또는 만들기 → 저장한 초안 → 이어서 수정하기 | GET `/v1/debates/{id}` |

기존 홈·글꼴·로고·툴바·카드 스타일을 유지합니다. 새 화면은 기존 공통 컴포넌트를 사용하고 Stack으로 열립니다. 새 탭은 만들지 않았습니다.
새 기능은 `api` 모드에서 사용하며 `mock` 모드의 기존 데모 기능은 유지합니다.

## 기능별 설명

### AI 요약

서버에 이미 생성된 찬성/반대 요약의 본문·생성 시각·근거 의견 ID를 표시합니다. 유보 요약은 만들지 않습니다.
빈 목록이면 “아직 요약 없음”을 표시합니다. 조회는 AI 생성 요청이 아닙니다. 생성 작업·실행 주기는 BE/AI 담당 범위입니다.

근거 의견 버튼은 기존 의견/답글 화면으로 이동합니다. 단일 원문 GET이 BE에 없어 이전에 불러오지 않은 원문은 캐시 안내와 답글 목록만 보일 수 있습니다.
단일 원문 조회 API가 추가되면 `api-thread-screen.tsx`와 조회 서비스를 보완하면 됩니다.

### 서버 시간

휴대폰 설정 시각 대신 서버 시각에 통신 지연 절반과 `performance.now()`의 경과 시간을 더해 계산합니다.
화면이 보일 때 1초마다 표시를 갱신하고 15초마다 서버에 다시 확인합니다. 화면을 떠나면 타이머·요청을 정리합니다.
마감 시 상세 화면의 참여·의견·입장 변경 진입을 막습니다. 실제 쓰기 권한과 마감 여부는 서버가 최종 검증합니다.
시간 조회 실패 시 오류·재시도 버튼을 표시하고 상세 화면의 쓰기 진입을 잠시 막습니다.
입장·의견 작성 화면도 API 모드에서는 장치 시계로 조기 마감시키지 않고 서버의 토론 상태를 사용합니다.

이 API만 응답 포장 없이 값을 바로 반환하고 시간에 `+09:00`이 붙을 수 있어 별도 파서를 사용합니다.
숫자 ID도 안전한 정수 범위에서 처리하지만, 이미 정밀도를 잃은 큰 숫자 ID는 거절합니다. BE에서도 문자열 ID로 통일하는 것이 좋습니다.

### 내 입장 변경 이력

로그인한 내 변경 기록을 최근 순서로 표시합니다. 최초 참여는 변경 이력에 포함되지 않습니다.
`persuasionId`는 영업 기록 ID이므로 의견 ID로 간주해 잘못된 링크를 만들지 않습니다.
미참여 토론 조회 등은 서버의 권한 오류를 안내합니다.

### 알림

전체/미읽음 필터·서버 미읽음 수·cursor 더 보기를 연결했습니다. 중복 알림을 합치고 반복 cursor로 무한 조회하지 않습니다.
`DEBATE` 대상 알림은 해당 토론으로 이동합니다. 그 외 대상은 응답으로 경로를 알 수 없으면 링크를 만들지 않습니다.
현재 **읽음 변경 API가 없으므로** 열었다고 읽음 처리하거나 미읽음 수를 줄이지 않습니다. 빈 목록에 예시 알림을 넣지 않습니다.
실제 알림 생성·발송 여부는 BE에서 확인해야 합니다.

### 초안 저장·수정·게시

1. 주제·방식·제목·내용을 입력하고 **게시 전 초안 저장**을 누르면 서버에 DRAFT를 만듭니다. 코인을 사용하지 않습니다.
2. 내용을 바꾸고 **초안 변경 저장**을 누르면 같은 ID에 PATCH합니다.
3. **저장한 초안 → 이어서 수정하기**에서 서버 내용을 다시 읽습니다.
4. 마지막 단계에서 게시하면 저장하지 않은 변경을 먼저 PATCH하고 기존 게시 API를 호출합니다. 코인 1개는 게시 때만 사용합니다.
5. 다른 작성자의 초안과 게시된 글은 수정할 수 없습니다. 서버의 403/409 오류를 안내합니다.

**전체 내 초안 목록 API는 아직 없습니다.** 목록은 이번 앱 실행 중 저장하거나 불러온 ID만 기억합니다.
내용은 서버에 남지만 FE의 목록은 새로고침·앱 재시작·로그아웃 시 비워집니다.
초안 ID를 알고 있다면 로그인 후 `/discussions/create?draftId=초안ID`로 다시 불러올 수 있습니다. 삭제 API도 없어 삭제 버튼은 만들지 않았습니다.

초안 생성 응답이 끊기면 실제 생성 여부를 알 수 없어 자동 재생성을 막습니다.
PATCH 응답이 끊기면 게시 전에 선택한 내용을 다시 저장해 서버 내용을 확정합니다.
게시 응답 유실 시 같은 초안·같은 멱등성 키로 재시도하며 결과 확인 전 편집을 막습니다. 확실한 4xx 거절 시 편집을 다시 허용합니다.
재시도 기록은 메모리이므로 불명확한 상태에서 새로고침·로그아웃했다면 BE에서 상태를 먼저 확인하세요.

## 실제 서버 검증

2026-11-11, `https://dev-api.yeongup.shop`에 실제 FE HTTP gateway로 접속했습니다.

- 요약 GET 성공. 확인한 토론은 빈 목록이었습니다. 본문·근거 ID가 있는 응답은 단위 테스트로 검사했습니다.
- 진행 토론 12, 종료 토론 16의 시각·마감·읽기 전용 상태를 확인했습니다.
- A는 빈 이력, B는 토론 16의 반대→찬성 이력과 영업 기록 ID를 확인했습니다.
- A/B 알림 목록과 A 미읽음 필터 성공. 모두 알림 0개/미읽음 0개였습니다. 알림이 있는 경우와 페이지 연결은 단위 테스트로 검사했습니다.
- A가 **초안 17**을 만들고 같은 ID로 제목·본문 수정, 다시 불러오기를 확인했습니다. **게시하지 않아 코인 차감은 없습니다.** 검증 초안은 서버에 남겨 두었습니다.
- B의 A 초안 GET/PATCH는 403, A의 게시된 토론 16 PATCH는 409 `NOT_DRAFT`로 거절됐습니다.
- 로그아웃 후 보호 요청 차단과 B에게 A의 초안 목록이 남지 않는 것을 확인했습니다.

검사는 Node에서 실제 요청 코드를 실행한 서버 통합 검사입니다. 브라우저 클릭이나 휴대폰 실기기 검사는 별도입니다.

최종 점검: TypeScript·ESLint(경고 0)·단위 테스트 **64개**·웹 HTTP/SSR **27개 경로**·공개 API/CORS 검사가 통과했습니다.
Android/iOS/Web 전체 번들도 생성했습니다(`.expo/remaining-api-export`, Git 제외).
검사용 웹 서버는 종료했으며 Commit·Push·PR 생성·Merge는 수행하지 않았습니다.

## 남은 범위

- BE/AI에서 요약·알림을 생성한 뒤 앱의 실제 본문·원문 이동·페이지 전환을 확인합니다.
- 읽음 변경·전체 초안 목록·단일 원문 조회 API가 생기면 확장합니다.
- 업보트/다운보트·신고·지갑/코인 내역·프로필 수정·카카오 인증은 해당 BE API와 별도 연동이 필요합니다.
- 실제 휴대폰·브라우저에서 로그인 → 초안 저장·이어 쓰기 → 게시, 계정 교체, 마감 전후를 최종 확인합니다.
